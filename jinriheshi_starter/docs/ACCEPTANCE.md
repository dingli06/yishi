# 验收案例与发布门槛

本文件是后续应用与数据扩充的验收要求。案例存在不表示已经实现或通过。当前代码实际执行结果以测试输出和质量报告为准。真实 HowToCook 样本与合成边界样例分开统计。

当前没有 HTTP 服务、微信页面或事件持久化；相关案例是目标验收。参考推荐尚未实现精力/省事分值，不将其列为当前已通过能力。种子没有 verified 总时间、主动时间和人数范围；严格时间/人数返回 `no_candidate` 是预期基线。默认 production 当前也应返回 `no_candidate`，因为尚无已发布内容。

## 1. 验收层级

| 层级 | 内容 | 可以证明什么 |
| --- | --- | --- |
| 数据基础 | 源锁、哈希、Schema、字典引用、原文证据、可重复构建 | 数据格式、来源和构建流程一致 |
| 规则验证 | 硬筛选、软偏好、器具/材料组合、未知值、去重 | 在给定数据前提下规则正确 |
| 内容审核 | 完整食材、条件、份量、时间口径、图片许可 | 对应条目具备指定用途的发布资格 |
| 应用集成 | API、状态、权限、幂等、并发、客户端交互 | 各模块联通且边界可执行 |
| 真实使用 | 开发者工具、真机、试做和试用 | 在约定外部环境与真实操作中可用 |

不能用上层的“格式校验通过”代替下层的内容真实或实烹验证。

## 2. 数据与构建

| ID | 条件/操作 | 预期 |
| --- | --- | --- |
| D01 | 对固定锁重复构建 | 业务数据与稳定 ID 一致；运行时间不造成全量内容漂移 |
| D02 | 任一 raw 文件 bytes 被更改 | 哈希校验失败并定位路径；不继续当成可信来源 |
| D03 | 下载中断或文件缺失 | 不生成声称完整的成功 manifest；可安全重试 |
| D04 | 原文更新但 overlay 的原始哈希未更新 | 拒绝静默应用或进入明确冲突队列 |
| D05 | 引用不存在的食材/器具 ID | 构建/校验失败，不自动造出占位字典项 |
| D06 | 无依据的菜系、时间或营养值 | 保留未知或待审核，不默认补值 |
| D07 | 凉拌黄瓜的步骤/计算出现原料清单未列的材料 | 审核能发现盐、香油、蚝油、白糖等跨节信息；严格食材判断不能只读首节 |
| D08 | 生米与熟米饭、干货与鲜货 | 不作为完全相同的执行条件匹配 |
| D09 | 修改一条已发布做法的步骤 | 形成新版本；旧反馈与收藏能定位原版本或得到明确失效提示 |
| D10 | 原始图片链接存在但许可/可用性未知 | 不自动下载为公开成品图；显示合法占位 |
| D11 | 导入器遇到陌生章节/格式 | 保留原文并报告异常，不静默丢失全部步骤 |
| D12 | 第二来源出现同名不同配方 | 不仅按名称合并；产生待核对关联 |

## 3. 推荐硬条件

| ID | 条件/操作 | 预期 |
| --- | --- | --- |
| R01 | 严格 15 分钟，只有“源文约 15 分钟”且未满足严格时间资格 | 不进入严格时间候选；开发预览可显示来源估计 |
| R02 | 时间未知或前提要求提前浸泡/过夜 | 不进入即时严格时间候选 |
| R03 | 丼饭需要米饭，用户只有生米 | 不能按已有熟饭的时长判断；使用匹配前提的版本或排除 |
| R04 | 器具为刀 AND 砧板 AND（炒锅 OR 平底锅） | 缺刀/砧板失败；满足其一锅具成功；不把所有 OR 选项都当必需 |
| R05 | 用户只有电饭煲，版本还必需炒锅 | 排除，即使正文提到了电饭煲 |
| R06 | 只用已确认食材，缺必需油盐 | 不默认有；提示缺料或返回无候选 |
| R07 | 葱花明确可选且缺失 | 不仅因为缺葱花排除；不把其余必需料变可选 |
| R08 | 一组材料允许 A/B 二选一 | 有 A 或 B 可满足该组；全无不满足；无法确认替代关系时不擅自替代 |
| R09 | 用户排除某成分，菜谱含成分未知的复合调料 | 不能声称已满足严格排除条件 |
| R10 | 食材种类匹配但库存数量未知 | 不显示“足量”；严格数量模式必须返回未满足/待确认 |
| R11 | 用户选择“一碗解决”，候选只是配菜 | 不宣称完整一餐；除非有明确主食版本与材料 |
| R12 | 硬条件失败但软评分最高 | 永远不入选；随机不绕过硬筛选 |
| R13 | 菜系未知但用户仅表示偏好 | 可在其他条件合格时保留，不编造菜系匹配理由 |
| R14 | 用户严格只看某菜系，菜系未知 | 排除 |
| R15 | 公开请求传入开发预览/跳过审核等字段 | 忽略或拒绝，不使开发样板进入生产推荐 |
| R16 | 当前种子请求严格人数 | 因缺少 verified 人数范围而无候选；不把原文人数提示直接当已验证范围 |
| R17 | 当前请求传入尚未定义的精力分值参数 | 按契约拒绝未知字段；界面不显示可用的省事筛选 |
| R18 | 后续启用精力排序（目标功能，尚未实现） | 基于已定义的主动操作/负担数据，能解释评分；不得仅按步骤数或难度星级冒充 |

## 4. 随机、去重与解释

| ID | 条件/操作 | 预期 |
| --- | --- | --- |
| S01 | 多个合格候选，测试注入固定随机源 | 结果可复现；生产无需暴露随机种子 |
| S02 | 某菜有多个做法版本，本轮已展示其一 | 其余版本不能作为“新的一道”再次出现 |
| S03 | 本轮看完所有菜品 | 明确提示耗尽，等待用户开启新一轮 |
| S04 | 软偏好没有可用数据 | 不生成“更省事/更合口味”等无依据理由 |
| S05 | 多项条件共同造成空结果 | 原因与实际检查一致；建议放宽需用户选择，不承诺单项一定有效 |
| S06 | 并发请求下一道 | 曝光和会话序号一致，无丢失更新或无记录重复 |

## 5. 事件与权限

| ID | 条件/操作 | 预期 |
| --- | --- | --- |
| E01 | 接受后立即退出详情 | 不增加做过次数 |
| E02 | 收藏、接受、做过分别发生 | 保存三个不同语义，互不自动推导 |
| E03 | 同事件 ID、同正文网络重试 | 只产生一次影响，返回可识别的原结果 |
| E04 | 同事件 ID、不同正文 | 返回冲突，不静默覆盖 |
| E05 | 用户操作另一主体的会话/收藏 | 被拒绝，不泄露对方数据 |
| E06 | “今天不想吃” | 仅作用于约定本轮/当天，不能永久拉黑 |
| E07 | 明确确认“一直不吃”再撤销 | 长期设置可保存、可撤销，历史事件仍有记录 |
| E08 | 事件引用已不存在/已下架版本 | 按契约明确处理；不把另一个版本作为原版本 |
| E09 | 用户修改条件后旧请求迟到 | 不能覆盖新条件版本的当前卡片 |
| E10 | 客户端时间异常 | 不能覆盖服务端排序和幂等逻辑 |

## 6. 客户端与接口

| ID | 条件/操作 | 预期 |
| --- | --- | --- |
| U01 | 不填任何偏好开始 | 能发起请求；按当前允许内容返回结果或明确的空结果 |
| U02 | 调整本轮条件 | 界面状态与请求一致，不未经确认改变长期设置 |
| U03 | 接受卡片进入详情 | 菜名、材料、步骤及版本与卡片一致 |
| U04 | 网络失败后重试 | 保留输入，不重复反馈，不凭空切换当前卡片 |
| U05 | API 返回未知枚举或结构不符 | 可定位的错误处理，不默认为所有条件通过 |
| U06 | 正文包含 HTML/外链媒体/命令片段 | 安全按内容呈现，不执行脚本、系统命令或自动媒体请求 |
| U07 | 时间、图片或份量未知 | 清楚显示未知/占位；不出现 0 分钟、假成品图或虚构份量 |
| U08 | 用户清空长期设置或收藏 | 当前主体的数据正确更新；跨主体不受影响 |
| U09 | 当前发布集合缺少严格时间/人数能力 | options 返回不可用与原因，界面不暗示支持；手工构造严格请求仍受服务端规则约束 |
| U10 | 详情与 options 按 OpenAPI 输出 | 分别满足 PublicRecipe 与 Options；不携带额外内部字段，空值及能力状态正确 |

## 7. 后续生产门槛

必须形成可审阅证据，而不只打勾：

1. 发布内容来源与权利状态可追溯；生产集合不存在开发预览条目。
2. 每个对外开放的硬条件均有对应字段审核门槛，不能通过缺失值绕过。
3. 关键数据、规则、权限与幂等案例通过；未覆盖的边界有明确限制。
4. 在约定场景上统计候选覆盖。建议目标为 80 个场景中至少 90% 各有 5 个不同菜品；当前仅作为目标。
5. 完成真实微信开发者工具和目标设备验证，记录 AppID 对应环境、版本、日期、操作和结果；不在公开记录中保存密钥。
6. 能执行数据下架、版本回滚与配置恢复；发布集合与应用版本可对应。
7. 实烹与人工内容审核分别保留实际参与者/方式和适用条件，禁止以 agent_generated 的记录冒充。

## 8. 验收记录模板

每次记录：案例 ID、数据版本、应用版本、环境、使用真实源/合成样例、输入、预期、实际结果、通过/失败/未运行、证据路径、缺陷与修复版本。截图不能替代服务器状态与事件数量的检查；测试通过也不能代替实烹时间。
