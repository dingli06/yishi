# 可直接交给开发 Agent 的任务书

## 主任务

在当前数据工程基础上，实现「今日何食」微信小程序首版。用户以时间、精力、食材和偏好表达当下条件，系统返回一个符合硬条件的具体做法版本，支持接受、换一道、收藏、查看步骤和记录做过。

数据源已经选择 HowToCook。先复现仓库离线流程，然后按下列任务推进。不重新比较供应商，不跳过数据资格直接把全部原文投入生产，不在已有核心逻辑之外另写一套不一致的筛选规则。

## 执行与完成记录

每个任务提交：修改文件、实际命令与退出结果、验收案例、未完成事项、下一任务依赖。现有 starter 的真实完成状态以 README、代码和本次验证为准；下表描述后续开发任务，不将其预标为已完成。

### T00：复现基线并确认契约

- **输入：** README、Schema、源锁、raw、overlay、测试和当前生成数据。
- **工作：** 在干净工作区执行 README 的离线构建、校验、测试与推荐演示；核对 raw 数量、种子数量、审核状态和数据库导出是否与实际一致。
- **输出：** 基线验证记录；发现问题时提交最小修复与复现案例。
- **验收：** 不依赖网络能读取随包数据并完成支持的离线流程；重建结果稳定；预览与生产资格明确区分。
- **依赖：** 无。未完成此项不得开展依赖数据契约的前端联调。

在项目根目录依次执行下列命令。首次安装依赖需要可用的 Python 包源；安装完成后，随包数据的构建、验证、测试和推荐演示均使用本地文件。

```bash
python -m pip install -r requirements-dev.txt
python scripts/fetch_howtocook.py --verify-only
python -m jinriheshi build
python -m jinriheshi validate
python -m unittest discover -s tests -v
python -m jinriheshi recommend --request examples/request_basic.json --mode development --seed 42
python -m jinriheshi recommend --request examples/request_basic.json
python -m jinriheshi export-sqlite --output data/generated/recipes.sqlite
```

依赖文件固定 JSON Schema 校验库 `jsonschema==4.26.0`。Windows 使用同一套命令；若机器仅提供 `py` 启动器，可将开头的 `python` 换成 `py -3`。这些是执行指令，不代表本文件记录了执行结果。

预期认识：development 使用种子进行预览；默认 production 由于当前 0 条已发布而返回 `no_candidate`。严格时间/人数条件因缺少 verified 字段也应为空。不能为使样例“有结果”而伪填时间、人数或发布状态。生成目录为 `recipes.jsonl`、`seed_recipes.jsonl`、`catalog.json`、`build_report.json`；导出后另有 `recipes.sqlite`。

### T01：冻结首版接口与选项字典

- **输入：** `PRD.md`、`ARCHITECTURE.md`、当前 Schema/契约及 T00 结果。
- **工作：** 明确请求中的硬条件、偏好、库存模式、份数、会话和幂等字段；确认前端选项值与字典 ID 对应；给出成功、空结果、冲突、失效版本和无权限样例。
- **当前对齐点：** 复用已定义的 Options/PublicRecipe DTO、expected_revision/session_revision 和 permanent_excluded_ingredient_ids；验证公开投影及各示例。仍需设计匿名/登录 token 的签发流程、收藏读取和常用设置端点。见 `API.md`；现有 OpenAPI 不等于完整 HTTP 实现。
- **输出：** 可校验的接口契约、类型、错误码与示例；若需要变更现有契约，附迁移说明。
- **验收：** 所有样例通过契约校验；任何首屏选项均能落到具体字段；未知值和默认行为无歧义。
- **依赖：** T00。

### T02：完成样板审核与内容管理入口

- **输入：** 30 条样板、原文、字典、overlay、质量报告、`SEED_REVIEW.md`。
- **工作：** 提供原文与字段对照、漏料提示、审核状态修改、发布/下架、按条件查看覆盖的最小管理工具。修正字典和 overlay，通过构建生成结果。为未确定字段建立审核队列。
- **输出：** 管理入口/命令、审核记录、发布检查与候选覆盖报告。
- **验收：** 生成数据不能绕过发布检查；agent 核对与人工确认分开；上游原文变化使旧审核失效或进入待复核；原文不被改写。
- **依赖：** T00；涉及 API 时依赖 T01。
- **说明：** 人工审核、试做需要真实记录。Agent 不得自签“已人工审核”或生成假实烹数据。

### T03：实现应用 Repository 与持久化

- **输入：** 统一数据模型、本地 SQLite 镜像、T01 契约。
- **工作：** 通过 repository 读菜品、具体版本、发布集合和候选；为会话、曝光、收藏、事件设计持久化。生产数据库选择后提供迁移，不让推荐逻辑依赖 SQL 方言。
- **输出：** repository 实现、迁移脚本、数据导入与回滚说明。
- **验收：** JSON/SQLite 或替代实现对同一测试数据返回等价领域对象；未发布内容不出现在生产查询；重导入幂等；引用不存在的食材或版本失败。
- **依赖：** T01。

### T04：实现应用推荐服务

- **输入：** 参考推荐逻辑、T01 契约、T03 repository、边界样例。
- **工作：** 复用或等价移植硬筛选、软排序、随机、多样性和解释逻辑；补齐应用会话中的去重与候选耗尽行为。前提、器具 AND/OR、替代组和未知值按契约处理。
- **当前限制：** 参考逻辑支持口味、菜系、口感、优先食材与尝新，不支持低精力评分。若首版要开放精力入口，先补 active/负担数据及契约，再增加逻辑与验收；不能把难度星级当现成替代。
- **输出：** 可调用的领域服务、可重复测试和理由生成器。
- **验收：** 硬条件不被分数或随机绕过；同菜多版本本轮只展示一次；空候选原因与真实规则一致；生产请求不能切换为开发预览。
- **依赖：** T01、T03；生产发布集合依赖 T02。

### T05：实现反馈、会话和长期偏好

- **输入：** T01 事件契约、T03 持久化、PRD 拒绝规则。
- **工作：** 实现接受、拒绝、收藏/取消、做过事件；分离本轮与长期偏好；实现事件幂等、所属关系校验、会话版本和并发下一条操作。
- **输出：** 事件服务、状态迁移与并发/重试测试。
- **验收：** 接受不增加做过计数；同事件重试只生效一次；同键不同正文冲突；不能操作另一用户会话；并发下一条不破坏曝光去重。
- **依赖：** T01、T03。

### T06：实现后端 API 与服务端权限

- **输入：** T01 契约、T04/T05 服务。
- **工作：** 提供选项、菜谱详情、推荐、反馈、收藏和常用设置接口；实现参数校验、错误映射、身份/匿名主体、速率限制与必要日志。开发预览只在可信开发环境开放。
- **输出：** 可本地启动的 API、环境变量示例、接口验证记录和部署说明。
- **验收：** 请求与响应符合契约；缺少身份或越权访问失败；不泄露凭证和内部审核备注；未知值没有被框架默认值误改；在干净环境能够按说明启动。
- **依赖：** T04、T05；只读接口可在 T03 完成后提前并行。

### T07：实现微信小程序页面与状态

- **输入：** PRD、T01 契约、T06 本地或测试服务。
- **工作：** 使用原生 TypeScript 实现首页条件、推荐卡、详情、收藏、常用设置。所有数据通过应用接口；条件可跳过，错误可恢复；未审核图片使用占位；对来源估计与未知值采用明确文案。
- **输出：** 小程序工程、配置模板、页面状态与交互说明。
- **验收：** 端到端完成发起→换一道→接受→详情→收藏→做过；加载/空结果/候选耗尽/网络重试均可操作；没有前端绕过硬条件的分支。
- **依赖：** T01 可先用契约 mock 进行界面开发；真实联调依赖 T06。
- **外部验证：** 需真实 AppID 和微信开发者工具；缺少环境时如实标为待验证，不阻塞可完成的代码工作。

### T08：完成数据覆盖与可用性验证

- **输入：** T02 发布集合、T04 推荐服务、T07 界面。
- **工作：** 预先定义受支持场景，统计每组候选数量、空结果原因、重复菜品和数据缺口；邀请小范围试用，记录决策卡片数与拒绝原因；优先补覆盖空缺。
- **输出：** 场景清单、覆盖报告、数据补充任务、真实试用记录。
- **验收：** 不用未审核数据补足数量；低覆盖选项有明确提示或收窄；测试集与真实用户样本分别说明。
- **依赖：** T02、T04；用户试用依赖 T07。
- **建议目标：** 80 个约定场景中至少 90% 各保留 5 个菜品候选。目标可按首版范围调整，不能伪报达成。

### T09：集成验收与上线准备

- **输入：** T00—T08 输出、`ACCEPTANCE.md`。
- **工作：** 执行数据、服务、客户端和权限验收；完成开发者工具及至少实际目标机型上的网络/交互验证；检查域名、包体、日志、配置、回滚和内容下架机制。
- **输出：** 验收记录、版本发布说明、未解决问题与回滚方法。
- **验收：** 严重硬筛选/数据泄露/幂等问题清零；各门槛均有证据；缺少外部配置的项目明确未通过；发布前使用的内容集合可追溯。
- **依赖：** T06、T07、T08。
- **边界：** 未获授权不发布线上服务、提交微信审核或联系内容供应商。先把可审核的版本和记录完成。

## 并行建议

T00 完成后先统一 T01。随后 T02 内容管理、T03 持久化与 T07 界面 mock 可并行；T03 完成后 T04 推荐与 T05 反馈可并行；再进入 T06 联调和 T08 覆盖验证。每个任务固定文件责任范围，接口变更先同步契约，再更新调用方。

## 可粘贴的执行指令

> 你负责开发「今日何食」首版。先完整阅读本仓库 AGENTS.md、README.md、docs/PRD.md、docs/ARCHITECTURE.md、docs/API.md、docs/AGENT_TASKS.md 和 docs/ACCEPTANCE.md。使用既有 HowToCook 固定快照和统一数据契约，先执行 T00 复现离线构建、验证与测试，修复基线问题，再依赖顺序执行后续任务。按数据源 adapter、规范化数据、repository、推荐领域、应用接口和微信小程序分层；优先复用已存在的代码。保持来源追溯、未知值语义、硬筛选、版本化、幂等和本轮/长期反馈作用域。开发样板不等于生产审核内容；没有真实试做、人审、AppID 或真机证据时明确标为待验证。精力排序尚未实现，严格时间和人数缺少 verified 数据，不伪填以获得推荐结果。每完成一项提交可运行产物、实际验证结果和剩余依赖，持续推进所有不依赖外部环境的工作。
